# Next big phase: harden the isolated rebuild DB

This phase deliberately modifies only:

`yacinedb_rebuild_test`

or another database named:

`yacinedb_rebuild_test_*`

The installer refuses the real `yacinedb`.

## Prerequisite

You must first have a successful:

```text
backend/sql/generated/yacinedb_rebuild_test-verification-report.json
```

generated by:

```powershell
.\scripts\run-rebuild-test-database.ps1
```

## Install hardening

```powershell
.\scripts\run-rebuild-test-hardening.ps1
```

Expected:

```text
Triggers: 6/6
ENABLED TR_...
TEST DATABASE HARDENING PASSED.
```

The triggers protect:

- Shelf creation/reassignment to ACTIVE stocks only.
- Equipment allocations to ACTIVE stocks only.
- Legacy Movement routes against INACTIVE stocks.
- Serial code immutability.
- Serial assignment to ACTIVE stock shelves only.
- Serial identities belonging only to serialized equipment.
- Inventory accepted-attempt/unit reconciliation consistency.
- Movement line quantity/type/serial consistency.
- Multi-line Movement source/destination stocks being ACTIVE.

## Then start backend against test DB

```powershell
.\scripts\start-backend-rebuild-test.ps1
```

This sets `DB_NAME=yacinedb_rebuild_test` for that process only.

## Then run real smoke flow

Use:

```text
backend/test/final-smoke.http
```

Test:

`Stock -> Shelf -> Equipment -> Serial -> IN -> TRANSFER -> OUT -> Inventory C1/C2/C3`

Do not touch real `yacinedb` yet.
